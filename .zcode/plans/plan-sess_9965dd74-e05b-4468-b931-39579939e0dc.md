# 前端构建（M-UI）：静态原型 → 吃真实数据的本地 Web 应用

## Context（为什么做）

M1 三段收口完成、M3~M7 引擎全线贯通后，前端仍是 1284 行的**静态原型**（`ui/prototype.html`，mock 甲公司、沪主板 3 套硬编码）。已拍板的 3 个决策（2026-11-13）：

- **P1 = 本地轻服务**：Python 标准库 `http.server` 起本地服务（零新依赖），前端能看已有结果、也能现场触发引擎跑新 run。
- **P2 = 原生多文件**：复用原型 356 行契约级 CSS（五态色板）+ 交互骨架，拆成 index.html + ES module JS，零构建工具、零 npm。
- **P3 = 三页全接真数据 + 修 V16/V17**：新建页（28 套套卡由规则库驱动 + 表单真跑引擎 + 补录弹窗生效）、结果页（result.json 全量驱动）、历史页（results/ 索引）；分 3 阶段交付，每阶段 git 检查点。

已核实的接口事实：
- 引擎入口 `run_eval(company_dir, rulebook_dir, fixtures_root, as_of, target) -> RunContext`（`ipo_eval_lab/engine/runner.py:81`），`.result` 即契约四段 dict，可直接 import 调用，**不需要 subprocess**。
- 补录注入路径：服务层把 base profile 拷贝到会话目录（`.scratch/ui-runs/<id>/profile.json`，覆盖 documentary/declared 字段），`company_dir` 指向该副本即可——真实 `fixtures/` 不动。留空字段引擎侧自然落 indeterminate（缺数据≠0，与原型语义一致）。
- `docs/demo/roadshow.html` 已验证「真实引擎输出 + 原型设计语言」可行，可作参照。
- V16 = 原型 `stdFor()` 仅返回沪主板 3 套、其余组合显示占位文案——28 套全加载后过时；V17 = 五态筛选缺「跨列口径切换」（任一列命中 vs 全部列命中）。

## 架构

```
ipo_eval_lab/webui.py        # 新增：本地服务（http.server，只绑 127.0.0.1）
                             #   GET  /            → ui/app/ 静态资源
                             #   GET  /api/meta    → 规则库版本/板块枚举/类型枚举/declared_no_sets
                             #   GET  /api/rulebook → 36 组摘要（套卡阈值/条款/法条号，新建页数据源）
                             #   GET  /api/companies → fixtures/companies/ 列表
                             #   GET  /api/results  → results/*.json 索引（只读 run 段）
                             #   GET  /api/results/<f> → 单份完整 result.json
                             #   POST /api/run     → {company, as_of, boards?, sets?, overrides?}
                             #                       → 会话 profile → run_eval → 落盘 results/ → 返回文件名
                             # python -m ipo_eval_lab.webui [--port 8080] 启动
ui/
  prototype.html             # 保留不动（设计 0007 的交付物基准）
  app/
    index.html               # 三页骨架（迁移原型 HTML，删全部 mock 内容节点）
    css/app.css              # 原型 CSS 迁移 + 数据态扩展
    js/main.js               # 入口/页路由/init
    js/api.js                # fetch 封装
    js/adapters.js           # result.json/规则库 → 视图模型（唯一知道契约键名的文件）
    js/format.js             # 五态徽章/单位/数字格式化（tabular-nums、亿元换算）
    js/dialogs.js            # 弹窗 + 焦点陷阱 + 补录表单
    js/page-new.js / page-result.js / page-history.js
```

要点：
- **事件绑定统一改委托**（原型 16 处内联 onclick 随迁移清除）。
- **结果文件命名**：沿 CLI 约定 `results/<company>_<asof>.json`；UI 带补录的 run 加时间戳后缀防覆盖。
- **不做**：移动端适配（0007 §6.4 维持桌面 1366+）、总分/维度分/雷达图（呈现禁令不变）、JSON 下载按钮（P9 拍板维持）。

## 实施步骤（每阶段一个 commit）

**阶段 0 · 服务骨架 + 文档**
- 新增 `docs/adr/0012-ui-webapp-form.md`（P1~P3 拍板记录）+ `docs/design/0010-ui-implementation.md`（目录/API 契约，短文）。
- 实现 `ipo_eval_lab/webui.py`：静态服务 + meta/rulebook/companies/results 四个 GET。

- `git commit` 检查点。

**阶段 1 · 结果页接真数据（核心页）**
- `adapters.js` + `format.js` + `page-result.js`：三页签（测评报告/深度分析/指标列表）全部从 result.json 渲染——套终态卡（progress/coverage/卡点/次弱）、层①叶表（五态+差距三分列+口径 pill 下钻）、情景推演（window_roll/growth）、层②四轴、层③归因 5×3、层④边界、段①②小卡。
- 对照 `results/base_co_2029_2025-06-30.json` 实数据逐区块核验。
- 浏览器过一遍三页签 → `git commit`。

**阶段 2 · 新建页（现场跑通链路）**
- 28 套套卡按 板块×类型 分组渲染（V16 占位文案就此删除）；表单联动（板块×类型双向、报告期+2）。
- 补录弹窗：overrides → POST /api/run → 会话 profile → 引擎 → 结果页跳转。
- 新增测试：POST /api/run 带 overrides 生成会话 profile 并产出 result（走真规则库+夹具）。
- `git commit`。

**阶段 3 · 历史页 + 收尾**
- 历史页读 /api/results：结论记录表（套终态逐套+路径输出）+ run 只读快照横幅 + 窗口滚动图（数据稀疏时优雅降级为占位说明）。
- V17：指标列表五态筛选加「任一列命中 / 全部列命中」口径切换。
- 更新 CONTEXT.md（#9 V16/V17 关闭注记、设计文档链接行）；浏览器全站验收。
- `git commit`。

## 验证

1. `python -m pytest tests/ -q` 全绿（现有 328 + 新增 webui 测试）。
2. `python -m ipo_eval_lab.webui` 起服务 → 浏览器（browser-use 工具）走查：新建页选 base_co_2029 → 选沪主板套 → 补录市值 → 点开始 → 结果页呈现真实判定 → 历史页能看到新 run。
3. 三份既有结果文件（base/qualified/unaudited）逐份在结果页打开核验渲染无 KeyError。

## 明确不做（本期外）

- U7 历史 run 叶子明细分档（需引擎按 run_id 冻结快照，属引擎侧）；
- 归母/扣非分项数值下钻展示（U6，字段已在 CompanyProfile，但弹窗文案层留到 UI 迭代再打磨）；
- 服务端鉴权/并发（单用户本地工具，只绑回环地址）。
