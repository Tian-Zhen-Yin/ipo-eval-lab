# ADR-0008：豁免语义（规则库 schema 支持「不适用某项」）

- 状态：Accepted（2026-11-12，用户拍板「扩规则库 schema 支持豁免」）
- 关联：ADR-0003（五态，`not_applicable` 已定义但**无产生路径**）、ADR-0006（引擎运行时与公式语义）、ADR-0007（进度与覆盖率）、[设计 0002](../../rulebook/models.py)（规则库 schema）、[设计 0005](../design/0005-engine-runtime-and-formula-semantics.md)（折叠语义）、[校准 0001 §3](../calibration/0001-set-inventory.md)（校准发现）

## 背景

M1 校准批次 3 完成后，43 套官方套中 6 套无法用现有 schema 表达，暴露两类问题：

**一、「不适用」条款无处安放。** 科创板 2.1.3 / 创业板 2.1.3 原文末句：

> 「处于研发阶段的红筹企业和对国家创新驱动发展战略有重要意义的红筹企业，**不适用"营业收入快速增长"的规定**。」

这是**法定豁免**——特定主体不适用某项标准。现有模型只有 `logic: all | any`（叶择一 / 全称），无「此条不约束我」这一档。红筹未上市第三档（midas `redchip_special`）正是这条豁免的落地位置。

**二、原文无对应条款的套。** 创业板 / 科创板**没有**「已在境外上市红筹」的标准条款——两板块 2.1.3 只覆盖「**尚未在境外上市**」红筹；而主板 3.1.4 确有此条（市值 2000 亿 / 200 亿 + 技术优势）。midas 存量对科创创两板块却各有一套 `redchip_listed`（2000 亿 / 200 亿+技术）。两者必居其一：

- **甲**：midas 存量沿用了主板口径，板块规则实际无此标准（存量冗余）；
- **乙**：创业板/科创板另有出处（未进本次五份 PDF 的部分，或历史版本已废止）。

原文库实证（2026-11-12）：五份现行版 PDF 中，**科创创两板块全文检索「境外上市」仅命中 2.1.3 的「尚未在境外上市」**；`2000 亿` 字样只在沪/深主板 3.1.4 出现。倾向甲，但**属法律裁定，不由校准管线自行认定**。

**三、既有设计其实已留了口子。** ADR-0003 定义五态含 `not_applicable`，并明确「折叠时 not_applicable 先剔除」——但引擎里**没有任何代码路径产生 `not_applicable`**：calc 只产出 `met / not_met / indeterminate / needs_review`。语义位已占位，缺的是「谁来判断某条不适用」的载体。

## 决策

### 1. 豁免是条文级的一等标注（不是新状态）

豁免**不新造折叠状态**。被豁免的叶直接产 `not_applicable`——ADR-0003 已定义的第五态，折叠时按既有规则「先剔除」。这样：

- 折叠三值不变（Kleene 双规则不动），不引入第四值；
- `not_applicable` 与「套级不适用」（applicability 层）同名不同层——**叶级 `not_applicable` = 该条不约束本主体**，**套级 not_applicable = 该套整体不适用**，二者不混。

### 2. schema：Clause 增 `exemptions` 字段

```yaml
- clause_id: rc_unlisted_g3_b1_c1
  display: 营业收入快速增长（三年复合增长率）
  law_ref: sse_main_2026#3.1.5
  exemptions:
    - when: {profile_field: company_stage, equals: rd_stage}
      excludes: [rev_3y_cagr]        # 命中 → 本 clause 的这些叶不约束
      note: '原文：处于研发阶段的红筹企业……不适用"营业收入快速增长"的规定'
```

- `exemptions` 是 **clause 级**列表，每条 = 条件（命中）+ 被豁免的叶（`excludes`）+ 引文注记；
- 条件用 `profile_field` + 运算符表达（等值 / 枚举 / in_list），复用 applicability 的谓词形状，但取自 `applicant_profile` 与**新增的申报事实字段**；
- 命中时：被 `excludes` 的叶 → `not_applicable`；未列入 `excludes` 的叶照常判定（豁免可只针对部分叶）。

### 3. `applicant_profile` 扩两个字段

豁免条件需要主体侧的事实（是否处于研发阶段等），这两个字段当前 `applicant_profile` 没有：

| 字段 | 类型 | 说明 |
|---|---|---|
| `company_stage` | `growth \| rd_stage \| strategic_significance \| None` | 研发阶段 / 国家创新驱动战略重要意义 |
| `redchip_status` | `listed \| unlisted \| None` | 境外上市状态（红筹专用） |

**必须显式、可空**——mock 样本无该字段时为 `None`，此时**豁免不命中**（保守：宁可按不豁免算，进人工复核，也不擅自免除法定义务）。这与 ADR-0003「null 永不进比较」同一原则。

### 4. 判定链：豁免在 calc 入口生效，优先级高于取数

豁免判断在 `evaluate_leaf` **取数之前**：命中 → 直接 `not_applicable` + 理由（引文 + 命中条件），**不查 metric、不取数**。理由是「不约束」而非「查不到」——两者语义相反，不可混。

### 5. 进度与覆盖率口径（ADR-0007 的补充）

- **coverage 分母**：被豁免的叶**不进分母**（不适用 ≠ 数据缺口）。豁免计入分母会让 coverage 虚低，触发不必要的「禁可达标」禁令；
- **progress 聚合**：豁免叶为 `not_applicable`，按 ADR-0007 规则「未定义叶不进 progress 聚合、只进 coverage 分母」——**但豁免叶不是未定义叶**，它有确定结论「不约束」。故豁免叶**既不进 progress 聚合，也不进 coverage 分母**；
- **不变量 #10 的补正**：「progress = 100 ⟺ 套 met」在有豁免时仍成立——豁免不产生约束，套的 met 只由实际约束决定。

### 6. 「原文无对应条款」不建模，走签核裁定

不因为 midas 有条目就造规则（那会把存量冗余写成法条），也不直接删（那是删证据）。处置：

- 4 套（创业板/科创板 `redchip_listed` × 2 套、红筹未上市第三档豁免档 × 2 套）进**人工签核队列**，材料含：原文检索证据（哪些 PDF 命中/未命中）、midas 存量内容、两种解释（甲冗余 / 乙另有出处）；
- 签核结论回来前，**这些套不进正式库**，`rulebook/_meta.yaml` 的 `declared_no_sets` 暂不改动（改了就等于替法务做裁定）；
- 引擎侧保证：**适用套为空时显式报错，不静默**（设计 0003 L0 检查项 0-7 已承诺，实现时补齐断言）。

## 后果

- 规则库 schema 扩一个字段（`Clause.exemptions`），向后兼容（默认空）；
- `applicant_profile` 扩两个可空字段，mock 样本需补（`None` 即可，不改变任何现有 golden 期望值）；
- 引擎 calc / fold / progress 三处需消费豁免；
- 「原文无对应条款」的 4 套**不在本 ADR 范围内**，由签核裁定；
- ADR-0003 的五态定义不变——本 ADR 只是补上 `not_applicable` 的**产生路径**，此前该状态是「有定义、无路径」。

## 被否方案

- **新造第四折叠态「exempt」**：会改写 Kleene 双规则与所有下游口径（进度、覆盖率、板块结论、UI 五态计数），代价与风险远大于收益——`not_applicable` 已足够表达，且 ADR-0003 的折叠规则已为它留好「先剔除」的位置；
- **把豁免写成「阈值无穷大」或「阈值 0」**：语义不同（那是数值不达标，不是法律上不约束），且会让进度算出一个假的 0% 或 100%；
- **按 midas 存量直接建红筹已上市套（科创创）**：以 trace 反向立法，违背 D4 权威源链（快照仅 trace，且快照自身带错已被实证）；
- **直接删掉这 4 套**：删证据；正确处置是进签核队列并留痕。
