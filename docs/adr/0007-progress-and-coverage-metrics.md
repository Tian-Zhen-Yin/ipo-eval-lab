# ADR-0007：进度与覆盖率双指标（不恢复 midas 式总分）

- 状态：Accepted（2026-11-10，用户「按照推荐的来调整」——P1~P6 全部按推荐）
- 关联：ADR-0001（facts 双层）、ADR-0003（口径与五态）、ADR-0006（引擎运行时与公式语义）、设计 0001 A5（**本 ADR 反转该条**）、设计 0005（第六个语义单点）、设计 0006（golden）、设计 0007（UI）、CONTEXT #6（**本 ADR 反转该决策**）

## 背景

midas 的结果模型给了一个总分（4 维度均分，不满 100 不通过）。本项目在设计 0001 A5 / CONTEXT #6 拍板**删除计分**（总分、维度分、pass_ratio）。

用户复盘时提出：完全取消量化指标，页面只剩文字判断，体验偏弱；希望保留分数，至少给一个量化锚点。同时指出：**midas 的「100 分才算通过」是对的，但不同项的权重应该不一样，而权重没有可参考的数据来源。**

三条事实需要先厘清：

1. **midas 的「100 才通过」不是缺陷**，是 AND 约束的正确表达（上市条件「均须满足」，无补偿条款）。缺陷在门旁边挂的那个数。
2. **权重不能进判定**：进判定意味着「财务差 40 分可被治理优 40 分抵消」，那是改法律语义。
3. **权重进展示即无来源装饰**：读者无法判断数字变化意味着什么，违反可复算 / 可预测变化。

即：权重无论放哪都不成立。问题不是「缺权重表」，而是「这个数字的职责边界错了」。

## 决策

1. **恢复量化指标，但形态是双指标而非单分数**：每套给 `progress`（达标进度 0~100）+ `coverage`（数据完整度 0~100）。**两者必须成对出现**——单出进度无法区分「接近达标」与「大部分没数据」；单出覆盖无判别力。
2. **判定与进度分离**：判定仍由硬叶决定（Kleene AND），进度**不参与判定**，也不被判定反推。
3. **套级聚合用 min**（与 AND 判定同源）：`progress = 100% ⟺ 套 met`（无未定义叶时）。**不引入权重表**。
4. **不恢复总分，不恢复维度分聚合**：维度（财务 / 资质 / 治理 / 板块定位）仅作 UI 展示分组，不聚合、不进判定、不进 narrative。
5. **补「次弱约束」**：min 给出最弱环，次弱给出「补完这个下一个是谁」，直接服务申报方避免返工。
6. **覆盖率 < 100% 时硬禁「可达标 / 预计能过」表述**，进度一律限定为「已评估部分」。

## 进度与覆盖率的定义

### 叶分数

```
s_leaf:
  met                                 → 1
  not_met 且有 gap_ratio（数值/计数叶） → 1 − gap_ratio
  not_met 且 thr = 0                  → 0        ← gap_ratio 无定义，不硬凑
  not_met 且为布尔/动作叶              → 0        ← 无「差多少」概念
  indeterminate / needs_review         → 未定义   ← 不是 0
```

**未定义叶绝不进聚合**——否则缺数据被算成 0 分，这正是 midas `isSatisfied(null)→0` 的病灶，不得重犯。

### 折叠（与 Kleene 双规则同源）

```
clause  logic=all → min(子叶)      logic=any → max(子叶)
branch  AND      → min(子 clause)
group   OR       → max(子 branch)
套      AND      → min(全部 clause 与 branch)
```

`min` 不是「每项权重相同」，而是「整体强度 = 最弱环强度」——约束系统的正确语义，且不需要任何外部参数表。

`max` 用于 OR 条款：落败支路不构成约束，不拉低分数（与 Kleene OR「任一 met 先满足」同向）。

### 覆盖率

```
coverage = 可判叶数 / 适用叶总数
```

可判 = met / not_met；未定义叶（indeterminate / needs_review）计入分母、不计入分子。

### 次弱约束

`progress` 的绑定叶（达成最小值的叶）→ 输出 `binding_clause_id`；次弱 = 排序后第 2 小的叶分数对应的 clause。

## 边界规则

| 情形 | 处理 | 理由 |
|---|---|---|
| thr = 0 的叶（三年净利均为正、净利 > 0） | met → 1；not_met → 0 | gap_ratio 分母为 0，无比例可言 |
| `all_periods` 量词（三年均为正） | 叶级二值（0 或 1） | 一个叶覆盖三年，逐年拆分会改变 item 语义 |
| 计数叶（专利数等） | gap_ratio = diff/thr；thr = 0 时同 thr=0 规则 | 有阈值就有比例 |
| 布尔/动作叶 | 恒 0（未做）或 1（已做） | 无「差多少」概念 |
| OR 落败支路 | 不计入次弱约束（Kleene OR 下不构成约束） | 与判定同向 |
| 未定义叶 | 不进 progress 聚合，只进 coverage 分母 | 缺数据不得算成 0 分（midas 病灶） |

## 为什么不用加权平均

| 方案 | 问题 |
|---|---|
| 均值（midas 通过率） | 「not_met 的套拿 85 分」，与 AND 判定脱钩，读者第一反应是「到底过没过」；且 null 进分母 → 不可复算 |
| 加权平均（用户设想的形态） | 权重表无数据来源；数字不可复算、变化不可预测 → 退化为心情件 |
| 加权后作判定 | 改法律语义（「均须满足」变「加权满足」） |
| **min（本 ADR）** | 与 AND 判定同源；达标 ⟺ 100%；无外部参数；卡点天然暴露 |

**结论：权重在 AND 约束系统里没有法律依据，而在展示层没有数据来源，故一律不引入。** 「不同项不一样」的真实含义由 `gap_ratio` 内生承载——距离权重来自差距本身，不需要外部参数表。

## 被否方案

- 恢复 midas 式总分（维度均分 + pass_ratio）：三个病灶原样保留（null 进分母、无 not_applicable、中间分泄露）。
- 恢复维度分聚合：维度间可加在上市条件语境里没有道理（治理优不能抵消财务差）。
- 引入权重表：无来源，违反可复算与可预测变化。
- 「总缺口 = Σ gap_ratio」作为唯一量化指标：把「差 1 项专利」与「差 6000 万」压成同量纲，OR 落败支路是否计入有歧义 —— v1 不做，v2 再议。
- 跨套用 progress 排序：跨套叶集不同 → 不可比。跨套排序是帕累托四轴的职责。

## 后果

- **反转 CONTEXT #6「删除计分」**：计分不是被恢复为「总分」，而是被替换为「进度 + 覆盖率」双指标；#6 的原始判据（避免恢复 midas 式总分）仍然成立。
- **反转设计 0001 A5**：同上，A5 反对的是维度总分与 pass_ratio，不是量化展示本身。
- 设计 0005 增加第六个语义单点（进度与覆盖率），与判定折叠共用同一套 Kleene 逻辑，保证进度与判定不可能各说各话。
- 设计 0004 §6 出口：`layers.gap.sets[]` 增 `progress` / `coverage` / `binding_clause_id` / `next_binding_clause_id`。
- 设计 0006 golden 增进度与覆盖率期望值（绑 rulebook_version）。
- 设计 0007 UI：套卡增进度条 + 覆盖徽章；**进度仅作展示，不进 narrative**。
- **跨期自比较是进度最值钱的用法**（同一套、同一批叶、同一口径）；跨套排序仍走帕累托。
