## 1. 为什么是「重设计」而不是「美化」

原始需求文档（[raw/req_docx_20261110](../../raw/req_docx_20261110/extracted_full.md) §IPO测评结果）的 UI 建立在本项目**已推翻**的模型上，照做即违反既有决策：

| 需求文档 UI | 项目已拍板的相反决策 | 依据 |
|---|---|---|
| 油量计总分 + 雷达图 + 四维进度条 | 计分**全删**（总分/维度分/pass_ratio） | 设计 0001 A5，#6 关闭 |
| （同上——**但保留量化锚点**） | **v0.5 修正**：删除的是「总分 / 维度分 / 雷达图」，**不是量化展示**——套卡内恢复**进度 + 覆盖率**双指标（无权重、min 聚合），见 §3.1 | [ADR-0007](adr/0007-progress-and-coverage-metrics.md) 反转 A5/#6 |
| 达标 / 不达标 两态 | **五态**：met / not_met / indeterminate / not_applicable / needs_review | ADR-0003（R3 推翻三态） |
| null→0、无数据当不达标 | 缺数据 = indeterminate，永不默认 0 | ADR-0003（修 midas `ResultEvalServiceImpl:149`） |
| 差异值/差异率单列 | 差距三分列：diff / required_delta / required_action | 契约 v0.2 §3.2（B8） |
| 「预计 N 年达标」 | 只输出 scenario 且必带 is_forecast；window_roll 输出确定性的进入年所需值 | ADR-0004（F5/F6 关闭，P8） |
| 维度内「取最高分标准」排序 | hard gate → **帕累托四轴**前沿，禁「最优」、禁推荐含 not_met 硬叶的套 | 设计 0001 §5.1（E1~E4） |
| AI 输出总分结论/优势/短板 | 项目内零 AI；输出 narrative_handoff JSON 供外部 agent 叙述 | D3/D4、ADR-0005 |

### 3.1 量化指标的视觉规范（v0.5 增补，E9）

> 语义与边界见 [设计 0005 §5.2](0005-engine-runtime-and-formula-semantics.md) 与 [ADR-0007](adr/0007-progress-and-coverage-metrics.md)。本节只定**呈现**，不定口径。

**落点**：套终态卡内，进度条 + 覆盖徽章**并排一行**（不拆两行，避免套卡再次长高）。

```
┌────────────────────────────────────────────────────────┐
│ 套一 · 主板标准一（净利润＋现金流/营收）    [未满足]      │
│ ▓▓▓▓░░░░░░░░░░░░░░░  40 分     数据覆盖 100%          │
│ 卡点：最近一年净利润 0.4 亿（需 ≥1.0 亿，差 60%）        │
│ 次弱：最近三年净利润累计 2.14 亿（差 7%）                │
└────────────────────────────────────────────────────────┘
```

| 元素 | 规则 |
|---|---|
| **进度条** | 按 `progress` 百分比填充；**颜色跟随套终态**（met=绿 / not_met=红 / indeterminate=灰 / needs_review=琥珀），不另设「分数配色」——避免颜色与五态两套语义打架 |
| **分数文本** | `tabular-nums`，整数 + 「分」；**不显示百分号**（那是覆盖率的位置） |
| **覆盖徽章** | `数据覆盖 100%`；< 100% 时改用**琥珀色 + 感叹号前缀**，鼠标悬浮显示未定义叶清单 |
| **卡点 / 次弱行** | 各一行，取自 `binding_clause_id` / `next_binding_clause_id`；次弱为 null 时整行隐藏（不留空位） |

**三条硬性呈现禁令**（与语义层禁令对应）：

1. **不显示总分、不显示维度分、不显示雷达图**——维度只作分组标题（财务 / 资质 / 治理 / 板块定位），不聚合、不排序。
2. **进度条旁不得出现「已达标 / 可达标 / 预计能过」字样**——`coverage < 100%` 时尤其禁止；进度只描述「已评估部分」。
3. **不提供跨套的进度排序控件**——跨套可比性归层②帕累托；进度只支持**同套跨期自比较**（测评历史页可显示趋势）。

**维度分组的例外**：若某套含多个维度类叶，维度名可作叶表的分组标题（如「财务与会计」），但**不给每组算分**——一旦每组有分，就会有「组间可加」的错觉。

## 4. Mock 数据（忠实设计 0001 附录 A 甲公司）

底稿：**以 [设计 0006 §5](0006-mock-data-contract.md) 定稿数值表为唯一来源**（逐年勾稽①②③平衡）：净利润（归母，扣非孰低）2022–2024 = **1.5 / 0.3 / 0.4 亿**；营收 **4.2 / 5.0 / 6.8 亿**（累计 16.0）；经营现金流 **0.5 / 0.6 / 0.7 亿**（累计 1.8）；归母净资产 10 亿；**预计市值未自估 → indeterminate**；发行后股本 8000 万、公开发行 25%、经营年限 5 年、股份有限公司 ✓。

> **数值收敛（2026-11-10，评审 0004 V3）**：本节 mock 数值原为营收 4.2/5.3/6.5 亿，与设计 0006 §5 定稿表（4.2/5.0/6.8 亿）分叉——累计同为 16.0 亿（累计型判定结论一致），但逐年增长率与 window_roll 结果不同（(6.8/5.0−1)=+36% vs (6.5/5.3−1)=+22.6%）。已统一到 0006 §5。

套结构 = **规则库 `rulebook/sets/`**（AR1：YAML 是唯一权威源，快照仅 trace）。当前仅 `cn_main_general_g1` 已落库；第二/三套待 M1 校准管线产出。原型内第二套市值门槛 **50 亿**（快照 350 亿系笔误，勘误事实见 [calibration/0001 §3-1](../calibration/0001-set-inventory.md)）——**此为 UI 演示数据，权威副本待落库**，不得据此认为规则库已含该套。

### 判定推演（本原型的「贯穿算例」）

| 套 | 叶判定 | 终态 | 四轴（not_met / max gap / 年数 / 数据不确定） | 路径输出 |
|---|---|---|---|---|
| 一（净利+现金流，3.1.2(一)） | 累计 2.2✓；1年 0.4 vs ≥1 ✗（差 0.6）；OR 支路：现金流 1.8✗ **或** 营收 16✓ → 条文✓ | not_met | 1 / 0.60 / — / 0 | **前沿**（互不支配：胜在数据确定） |
| 二（市值+净利+营收+现金流，3.1.2(二)） | 市值未自估?；净利✓；现金流 1.8 vs ≥2.5 ✗（差 0.7）；营收 6.8✓ | not_met | 1 / 0.28 / — / 1 | **前沿**（胜在缺口小） |
| 三（市值+净利+营收，3.1.2(三)） | 市值未自估?；净利✓；营收 6.8 vs ≥10 ✗（差 3.2） | not_met | 1 / 0.32 / — / 1 | **排除**（被二支配） |

- **无 recommendation**：三套均含 not_met 硬叶，契约禁止推荐——页面主叙事变成「最短缺口是标准一的 1 年净利润 0.6 亿」。这是新旧 UI 的本质分野：旧评分 UI 会给「87.5 分 · 部分达标」。
- **window_roll 演示**（附录 A 原例）：窗口滚到 2023–2025，进入年需 ≥ 2.0−0.7 = **1.3 亿** vs 2024 实际 0.4 亿（3.3 倍 > 2 倍阈值）→ 高风险。营收支路需 ≥3.5 亿 vs 6.8 亿 → 低风险。
- OR 支路救回（附录 A G1 例）、归因正交表落格（实例：「缺 2022 年数据」= missing_data × none；「最近年净利差 0.6 亿」= verified × numeric_gap；「自主研发国际领先待核查」= pending_judgment × none）均在页面可点验。
