## 1. 为什么是「重设计」而不是「美化」

原始需求文档（[raw/req_docx_20261110](../../raw/req_docx_20261110/extracted_full.md) §IPO测评结果）的 UI 建立在本项目**已推翻**的模型上，照做即违反既有决策：

| 需求文档 UI | 项目已拍板的相反决策 | 依据 |
|---|---|---|
| 油量计总分 + 雷达图 + 四维进度条 | 计分**全删**（总分/维度分/pass_ratio） | 设计 0001 A5，#6 关闭 |
| 达标 / 不达标 两态 | **五态**：met / not_met / indeterminate / not_applicable / needs_review | ADR-0003（R3 推翻三态） |
| null→0、无数据当不达标 | 缺数据 = indeterminate，永不默认 0 | ADR-0003（修 midas `ResultEvalServiceImpl:149`） |
| 差异值/差异率单列 | 差距三分列：diff / required_delta / required_action | 契约 v0.2 §3.2（B8） |
| 「预计 N 年达标」 | 只输出 scenario 且必带 is_forecast；window_roll 输出确定性的进入年所需值 | ADR-0004（F5/F6 关闭，P8） |
| 维度内「取最高分标准」排序 | hard gate → **帕累托四轴**前沿，禁「最优」、禁推荐含 not_met 硬叶的套 | 设计 0001 §5.1（E1~E4） |
| AI 输出总分结论/优势/短板 | 项目内零 AI；输出 narrative_handoff JSON 供外部 agent 叙述 | D3/D4、ADR-0005 |

## 3. 五态视觉规范（契约级，换色需过评审）

| 态 | 色值 | 用法 |
|---|---|---|
| met 满足 | #047857 / 底 #ecfdf5 | 实心绿点 |
| not_met 未满足 | #be123c / 底 #fff1f2 | 实心红点 |
| indeterminate 不可判 | #475569 / 底 #f1f5f9 | 灰点（缺数据≠0 的显性化） |
| needs_review 待核查 | #b45309 / 底 #fffbeb | 琥珀点（judgment 永不 met） |
| not_applicable 不适用 | #94a3b8 + **虚线边** | 计数守恒中单列，不入分母 |

其它 token：数字一律 `tabular-nums`；is_forecast 用琥珀 pill；「企业自估」限定用琥珀 pill；归母/扣非用蓝 pill。

## 4. Mock 数据（忠实设计 0001 附录 A 甲公司）

底稿：净利润（归母，扣非孰低）2022–2024 = **1.5 / 0.3 / 0.4 亿**；营收 **4.2 / 5.3 / 6.5 亿**（累计 16.0）；经营现金流 **0.5 / 0.6 / 0.7 亿**（累计 1.8）；归母净资产 10 亿；**预计市值未自估 → indeterminate**；发行后股本 8000 万、公开发行 25%、经营年限 5 年、股份有限公司 ✓。

套结构 = DB 快照（`mt_ipo_listing_standard` 沪主板·一般企业 sort1~4 → 官方 3 套）；第二套市值门槛 **50 亿**为 [calibration/0001 §3-1](../calibration/0001-set-inventory.md) 勘误修正值（快照 350 亿系笔误）。

### 判定推演（本原型的「贯穿算例」）

| 套 | 叶判定 | 终态 | 四轴（not_met / max gap / 年数 / 数据不确定） | 路径输出 |
|---|---|---|---|---|
| 一（净利+现金流，3.1.2(一)） | 累计 2.2✓；1年 0.4 vs ≥1 ✗（差 0.6）；OR 支路：现金流 1.8✗ **或** 营收 16✓ → 条文✓ | not_met | 1 / 0.60 / — / 0 | **前沿**（互不支配：胜在数据确定） |
| 二（市值+净利+营收+现金流，3.1.2(二)） | 市值未自估?；净利✓；现金流 1.8 vs ≥2.5 ✗（差 0.7）；营收 6.5✓ | not_met | 1 / 0.28 / — / 1 | **前沿**（胜在缺口小） |
| 三（市值+净利+营收，3.1.2(三)） | 市值未自估?；净利✓；营收 6.5 vs ≥10 ✗（差 3.5） | not_met | 1 / 0.35 / — / 1 | **排除**（被二支配） |

- **无 recommendation**：三套均含 not_met 硬叶，契约禁止推荐——页面主叙事变成「最短缺口是标准一的 1 年净利润 0.6 亿」。这是新旧 UI 的本质分野：旧评分 UI 会给「87.5 分 · 部分达标」。
- **window_roll 演示**（附录 A 原例）：窗口滚到 2023–2025，进入年需 ≥ 2.0−0.7 = **1.3 亿** vs 2024 实际 0.4 亿（3.3 倍 > 2 倍阈值）→ 高风险。营收支路需 ≥3.5 亿 vs 6.5 亿 → 低风险。
- OR 支路救回（附录 A G1 例）、归因 2×2（真实缺口/可补/需外部证据三类落格）均在页面可点验。

1. 仅铺开「沪主板 × 一般企业」组合；其余 40 官方套在选择时展示占位说明（引擎接入后由规则库 YAML 驱动渲染）。
2. 文案中的条文号 `3.1.2(一/二/三)` 为占位——法条库 `rulebook/legal/` 仍 `calibration_pending`，校准 #5 回填后替换。
3. 五态筛选暂为「未满足/不可判」「仅待核查」两档粗分；细分五档待指标列表信息密度反馈后再定。

## 7. 变更记录

### v0.2（2026-11-10）：结果页减复杂度

起因：评审意见「测评结果页是否太复杂」。诊断 = 实质复杂（契约四层，保留）× 呈现复杂（平铺/泄漏/冗长，修改）。拍板 **P1′ 三页签分区 / P2′ 四轴出套卡 / P3′ 注解折叠**（均按推荐）：

| 变更 | 内容 | 度量 |
|---|---|---|
| 三页签分区 | 结果页拆为 **测评报告**（默认：结论带+套卡+层①+情景+段①②）/ **深度分析**（层②四轴明细表+层③归因+层④边界）/ **指标列表**（矩阵） | 单页滚动 ~4800px → 报告页签 1595px |
| 套卡瘦身 | 删四轴小表与 axes_note、排除理由长文；换一句缺口摘要（excluded 全文降为 ⓘ 悬浮） | 套卡高度 -40%，前沿/排除标记保留 |
| 四轴明细表（新增） | 深度分析页签：一行一套 × 四轴 + 前沿/排除列 + 支配关系说明（含「无 recommendation」与 G6 声明） | 原 path-note 说明文字随迁 |
| 注解折叠 | 「旧 AND 模型错杀」「350 亿笔误勘误」等原理说明移入 data-tip ⓘ；正文只留判定结论 | 叶表「口径与依据」列平均 -1 行 |
