# 专业性问题清单：v0.1 全量审视（第一步）

- 日期：2026-11-09
- 性质：以投行 / 交易所审核视角，对 [CONTEXT.md](../../CONTEXT.md) v0.1、[ADR-0001](../adr/0001-facts-layer-granularity.md)、F5（含 D 方案与驱动级可达性）、[评审 0001](0001-gap-layer-design-review.md) 做**否定性**审视
- 取舍标准：**业务真实性与专业性优先**。改动代价只在文末作为后果说明，不作为保留理由
- 状态：第一步产物；第二步（自顶向下重设计）另行落文档

## 0. 结论

v0.1 在**工程结构**上成立（事实层/派生层分离、引用不复制、evidence 一等地），但在**业务语义**上存在系统性偏差，核心是三类：

1. **把审核判断降格为计分**：维度均分、通过率、单一 distance，在审核实务中都不存在。
2. **把「点判定」降格为「趋势预测」**：IPO 标准是按报告期数据做的**时点判定**，"还要几年"不是审核概念，只能作为明确标注的情景推演。
3. **把「门槛集合」降格为「提示词清单」**：套之间的择一关系、规则生效时点、特殊主体（红筹/未盈利）适用性、扣非孰低等口径，全部缺失。

因此 **CONTEXT.md v0.1 应整体替换**；ADR-0001 的"双层事实"结论保留但需修订；F5 的 D 方案推翻；"驱动级可达性"保留驱动分解，但"eta/还要几年"作为结论推翻。

## 2. 不专业条目清单

### A 组：评测单元与标准套建模

| 编号 | 条目 | 问题出在哪 | 为什么这不专业（依据） | 正确做法 |
|---|---|---|---|---|
| **A1** | `facts.sets[]` 的 62 个「板块×企业类型×套序号」组合 | 由 `listing_standard` 178 条条文做**笛卡尔积**生成 | 上市标准不是笛卡尔积：科创板第X套标准只对特定主体开放，红筹、未盈利、特殊行业各有专套；cross join 会造出**现实中不存在的套**，引擎会给企业算出"符合一个不存在的标准" | 套必须由规则原文**逐条定义**（`set_definition`：板块 + 适用主体谓词 + 该套条件清单），禁止按维度组合派生 |
| **A2** | `outcome.status = feasible / infeasible / undetermined` + `pass_ratio` | 用"通过率"表达一个套的满足程度 | 上市标准是**必要条件合取**：一套 6 个条件过 5 个 = 不满足，不存在"83% 上岸"。`pass_ratio` 会诱导外行得出"再努力一点就行"的错误结论 | 套内只能 `met / not_met / indeterminate`；套间是**择一析取**。`pass_ratio` 从契约删除 |
| **A3** | `sets[].set_no` 当排序键、"套名取 asset_name" | 隐含"第 1 套优于第 2 套" | 真实标准套是**并列可选**（创业板三套、科创板多套），企业按自身条件择优，不是等级序列 | 套只保留官方名称与编号，不参与排序；择优逻辑放层②，且必须显式说明"选择理由" |
| **A4** | 维度四分法 `financial_status / subject_qualification / governance_operation / sector_alignment` | 沿用 midas UI 的分组 | 这不是审核分类。法定分类是 L1 第二章四节：**主体资格、规范运行、财务与会计、募集资金运用**；板块定位（科创属性/三创四新/北交所创新性）是**另一维度**，不属于发行条件 | 改为三段式：`issuance_conditions`（四节）+ `board_positioning`（板块定位）+ `listing_standard`（市值/财务指标） |
| **A5** | 维度计分、总分、维度均分（原 #6） | 把合规判断折算为分数 | 审核没有"治理 78 分"。`是否有 1/3 独立董事` 与 `营收 3 亿` 不可通约；加权平均会掩盖**一票否决**项（如重大违法违规） | 取消总分与维度分。硬指标给数值判定，实质性判断给 `met / not_met / needs_professional_judgment`；**否决项单列**，命中即整体不满足 |
| **A6** | 未盈利 / 红筹 / 特殊行业主体缺失 | 61 项与 62 套只覆盖"常规盈利企业" | 科创板第五套标准、红筹标准、创业板未盈利标准是真实存在的上市路径；缺了它们会把**合规企业误判为不满足**，这是功能性错误 | 套定义引入 `applicant_profile`（盈利状态、注册地、行业属性、表决权架构）；不匹配时该套标 `not_applicable` 而非 `fail` |
| **A7** | `run.input.report_period` 仅为占位 | 无"三年一期""最近一期"等审计口径 | 主板看最近三年、创业板/科创板部分套看最近两年、部分指标看最近一年；且必须为**经审计**数据。口径错一年，结论就反 | `report_period {fiscal_years[], stub_period?, audit_status, audit_opinion}`；`audit_opinion` 必须为 `unqualified` 才构成发行条件（L1 财务与会计节） |

### B 组：指标口径与判定语义

| 编号 | 条目 | 问题出在哪 | 为什么这不专业（依据） | 正确做法 |
|---|---|---|---|---|
| **B1** | 净利润单值 + 单一 formula | 无法表达**扣非前后孰低** | L6 要求披露扣非前后净利润；审核实务按**孰低**判断是否达标。单值会系统性高估 | `measurement` 支持 `measures[]`：`net_profit` / `net_profit_excl_nonrecurring` / `lower_of_both`，判定取 `lower_of_both` |
| **B2** | "最近三年净利润累计"用一条区间判定 | 主板要求"**均为正**"且"累计不低于 X"，是两个不同量词 | "每年为正"是逐期全称量词（∀），"累计"是求和；一条 `op` 无法同时表达。混用会漏判"某一年亏损但累计为正" | 规则条件支持 `quantifier ∈ {all_periods, sum, avg, latest, cagr}`；`all_periods` 单独成判定 |
| **B3** | ROE 未区分加权平均 | 只写 "ROE" | L7 明确净资产收益率须按**加权平均**计算；北交所标准直接写"加权平均净资产收益率"。用期末净资产口径会得到不同数值 | 指标命名强制带口径后缀：`roe_weighted_avg`；公式库只允许加权平均实现 |
| **B4** | "研发投入占比"未区分研发费用 / 研发投入 | 单一 `rd_investment` | L3 的"研发投入"包含费用化 + 资本化，而利润表"研发费用"只含费用化；两者差额可能决定 5% 门槛是否达标 | 拆 `rd_expense`（费用化）/ `rd_capitalized` / `rd_investment_total`；科创属性判定用 `total`，并记录归集依据 |
| **B5** | "发明专利数量"只数数量 | 未区分申请/授权、是否应用于主营业务 | L3 要求"**应用于公司主营业务的发明专利 7 项以上**"，且实践中以**授权**为准 | 指标拆为 `invention_patents_granted` + `applied_to_main_business` 布尔；两者同时满足才计入 |
| **B6** | `check07` 同行 CAGR 为布尔自填 | `RAW()` + 底稿勾选 | 这是实质性判断，需**可比公司选取 + 同期间/同币种/同会计政策**口径，且是审核问询高频点；让申报方自证"是"不具证据力 | 降级为 `needs_professional_judgment`，输出"需可比公司清单与增长率对照表"，不给通过/不通过；若建基准库则改为计算式并留痕 |
| **B7** | 三态 `pass / fail / unknown` | `not_applicable` 与 `indeterminate` 被合并 | 红筹不适用某些条款，是"不适用"不是"缺数据"；合并后层③会把适用性问题误归为数据质量问题 | 五态：`met / not_met / not_applicable / indeterminate / needs_review`；`not_applicable` 不计入分母 |
| **B8** | `diff` / `gap_ratio` 对布尔项无定义 | 契约未禁止布尔项带 diff | "专利差 3 项"与"营收差 3000 万"写进同一字段，跨项聚合即失真 | 数值项才有 `diff`；分类项用 `required_delta {count}`；布尔项用 `required_action`。三者物理分列 |
| **B9** | 合规项（重大违法、股权清晰、同业竞争）当布尔 | 这类项不是事实，是**法律判断** | L1「规范运行」节与 L10 的判断依赖主管部门认定/处罚决定书；引擎无权下结论 | 输出 `needs_professional_judgment` + 所需证据清单（处罚决定书、无违法违规证明等），不得自判通过 |

### C 组：事实层与数据契约（ADR-0001 相关）

| 编号 | 条目 | 问题出在哪 | 为什么这不专业（依据） | 正确做法 |
|---|---|---|---|---|
| **C1** | `measurement` 为**单值对象** | 假设"一个指标一个值" | 同一指标至少有三个正交维度：合并/母公司、审计/未审、扣非/未扣非；L8 要求列报口径明确，实务取数必须能追溯 | `measures[]`，每项含 `{basis_of_preparation, audit_status, deduction_basis, period, value, source_ref}` |
| **C2** | `inputs[].source_ref` 为裸字符串 | 无法回溯到报表层级 | 审核取数链条：审计报告 → 报表 → 附注 → 科目 → 指标；且需记录**追溯调整**（会计政策变更导致历史数重述） | `source_ref {statement, note_no, line_item, period, audit_report_id, restated_from?}` |
| **C3** | `data_quality` 与 `cause` 混为一谈 | 层③把"数据质量 vs 真实差距"作为**一个**分类字段 | 这是两个正交维度：**可核验性**（能不能算、数据可不可信）与**实质障碍**（业务上是否构成障碍）。一项可以"数据完整但构成实质障碍"，也可以"数据缺失但业务无碍" | 拆成两个字段：`verifiability ∈ {verifiable, unverifiable, missing}` 与 `substantive_obstacle ∈ {none, remediable, structural}` |
| **C4** | `evidence` 只能装法规 | `doc_title / doc_no / article` 结构 | 审核还依赖《监管规则适用指引——发行类第X号》《审核问答》、会计准则解释、同类案例；装不下就会逼着把问答内容写成"法规" | 增加 `source_type ∈ {law, regulation, exchange_rule, guideline_qa, accounting_standard, case}` + `case_ref` |
| **C5** | `rulebook_version` 为单字符串 | 无法回答"按哪天的规则判定" | 规则变动频繁（2023 全面注册制、2024-04-30 门槛上调、科创板持续修订），且新规常有**过渡期**；用错版本直接得出相反结论 | `as_of_date` 决定适用规则集；结果必须回写 `applied_rule_versions[]` 与 `transitional_applied` |
| **C6** | 无"指标 → 报表科目"的映射实体 | 公式直接引用 `$指标编码` | 指标编码是 midas 内部约定，不是会计科目；缺映射就无法用外部审计报告独立复算，也无法做交叉核对 | 新增 `metric_definition`：指标 → 科目组合 + 取数规则 + 口径约束；公式只引用指标，指标必须绑定定义 |

| 编号 | 条目 | 问题出在哪 | 为什么这不专业（依据） | 正确做法 |

### E 组：四层分析的结论边界

| 编号 | 条目 | 问题出在哪 | 为什么这不专业（依据） | 正确做法 |
|---|---|---|---|---|
| **E1** | 层① `closest`：跨套选"最接近" | 用一个尺度比较不同性质的套 | "市值差 20%"与"专利差 2 项"不可通约；且"最接近"的套可能含否决项，距离再小也不可上 | 取消跨套标量排序。改为**逐套独立结论 + 阻塞项清单**；排序只在同一 `axis` 内做（硬门槛轴 / 属性轴分开） |
| **E2** | 层① "还要几年追上"作为结论 | 把时点判定变成趋势预测 | IPO 审核判定基于**报告期已实现数据**；增长率外推属投行的**情景推演**，必须声明假设、区间与不构成预测。单点年数是伪精确（r 差 10pct，年数差 3 年） | 降级为 `scenario_projection`：显式 `assumptions[]`、区间、`is_forecast=true`、仅供内部参考；结论体改为「缺口 + 整改幅度」 |
| **E3** | 层② `distance` 单一标量 + 按距离排序 | 把不可通约的差距求和 | 更严重：会推荐"离门槛最近但含一票否决项"的套。真实板块选择是**先筛否决、再看可行性/时间/成本/确定性** | 两级：①`hard_gate` 否决筛选；②剩余套做**帕累托前沿**（时间 × 整改项数 × 确定性），不压成单值 |
| **E4** | 层② "最优"未定义目标函数 | "最优"指代不明 | 投行的板块选择是多目标（定位契合度、门槛、审核确定性、估值、再融资便利），没有唯一最优 | 显式列出比较维度与权重来源（用户偏好/行业惯例），输出**推荐 + 备选 + 不推荐理由**，不称"最优" |
| **E5** | 层④ `narrative_handoff` 无免责与限定 | 只有可叙述单元与引用索引 | 任何对外文本必须含：数据来源、审计状态、规则版本、未核查事项、专业判断边界。否则 LLM 会写出"符合上市条件"这类**越界结论**（该结论只能由交易所作出） | 增加 `disclaimers[]`、`limitations[]`、`forbidden_claims[]`（如禁止输出"符合发行条件/保证过会"） |
| **E6** | 全文措辞"能否上岸/feasible" | 用确定的通过/不通过口吻 | 上市是行政许可，工具只能给"指标层面满足情况" | 统一措辞：`criteria_met / criteria_not_met / indeterminate`，附"基于所提供数据与指定规则版本"限定 |

## 3. 对既有决策的处置

## 5. 第二步要回答的问题（预告）

1. 真实决策对象是「企业在某板块某套标准下、按某规则版本、以某报告期审计数据，指标层面是否满足」——如何把这个句子直接映射成契约主键。
2. 评价单元按 L1 四节 + 板块定位 + 上市标准三段切分，如何与"套"的择一关系对齐。
3. 硬指标（可计算、有明确阈值）与实质性判断（需专业意见）如何分家，且后者如何在结果中"不产生分数、只产生待核查事项"。
4. mock 数据的七条勾稽约束如何落成可校验的 fixture。
5. 四层各自能承担/不能承担什么结论，以及对外措辞的禁用清单。
