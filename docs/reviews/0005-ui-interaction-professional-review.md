# 评审 0005：交互原型（设计 0007）的交互设计与专业性复核

- 日期：2026-11-10
- 性质：对 [设计 0007](../design/0007-ui-prototype.md) / [ui/prototype.html](../../ui/prototype.html)（UI v0.3 → v0.4）的**独立复核**——以投行 / 交易所审核视角与交互设计视角双维度审视，重点找**会被用户误读**与**会被专业读者质疑**的地方
- 方法：交互层（信息架构、可达性、状态反馈、术语一致性）+ 专业层（五态语义、口径可核验性、不编造、契约一致性）双向走查；每条发现给出「为什么会错」+「修完什么样」+ 可度量的验收标准
- 范围外：规则阈值内容正确性（属校准 #5）；视觉审美偏好（用户自评已过）；引擎实现（尚未实现）
- 结论：**可作为交互冻结基线**。共 17 条发现：P0×1（专业性硬伤）、P1×6、P2×7、P3×3；**全部 10 项可执行改进已于 UI v0.4 落地**（§4 对照表；其中 U4 经 **P9 = A 拍板（2026-11-11）撤销移除**，见 §4 注），另 7 条转实现期条目
- 处置提交：`e6ac927`（代码）+ `8b6bfef`（设计 0007 §7 回写）+ `608bf96`（本文归档）+ UI v0.5.1（P9 = A 按钮移除）

## 0. 总评

| 维度 | 评价 |
|---|---|
| **心智模型一致性** | ✅ 成立。原型没有沿用需求文档被推翻的「计分 / 通过率」模型，页面结构与契约 v0.2 的四层分析一一对应 |
| **五态完整性** | ✅ 成立。met / not_met / indeterminate / needs_review / not_applicable 五态在叶、套、路径、归因各层一致呈现，无第三态混用 |
| **缺口分层表达** | ✅ 优秀。diff（数值差）/ required_delta（计数差）/ required_action（布尔动作）三列分立，符合 ADR-0003 |
| **可核验性** | ✅ 成立。每个数字都带 `source_ref`，阈值可回溯条文 |
| **交互可达性** | ⚠️ **有缺口**：键盘焦点不可见、弹窗不响应 Esc、折叠头无语义 |
| **专业措辞** | ⚠️ **有硬伤（P0）**：板块定位「待核查」把**业务判不了**与**工程没做**混为一谈 —— 前者须交易所实质判断，后者是我方未实现 |

**白话**：这台原型**骨架和数字都是对的**，读者能一眼看懂「哪几套、差多少、为什么」；但它有两个地方**会让人读错**——一个是把「我还没做这个功能」写成了「这件事有问题」，一个是占位条文号看起来像正式引用。另有若干「点了没反应 / 键盘看不见焦点」的交互毛刺。10 项关键问题已在 v0.4 修完。

## 1. P0：专业性硬伤（1 项）

### U1 · 板块定位「待核查」混同了「业务判不了」与「工程没做」

**证据**：

- 设计 0007 §4 的 POSITIONING 段：状态 `review`，值文案「待核查」，工程注记「G-D 逐套映射待接入」。
- CONTEXT §5 #5 注记 **G-D**：IPO-41~61 板块匹配 21 套 → 段②逐套映射，属**实现期工作**。
- ADR-0003：`needs_review` 的语义是「需人工/外部证据判定」。

**问题**：这里有**两个性质完全不同的「未知」被塞进了同一个琥珀色徽章**：

1. **业务判不了**——板块定位匹配是交易所的**实质性判断**（企业是否属于「大盘蓝筹 / 成熟型企业」），即使 G-D 映射全部实现，结论仍须交易所认定，引擎只能给预判；
2. **工程没做**——G-D 逐套映射未实现，故无法给出「命中哪几套」的逐套归属。这是**我方能力缺口**，不是企业的问题。

用 `needs_review`（琥珀）单一状态表达两者，用户看到「板块定位 待核查」会合理推断「**这家企业定位有问题**」——而原型给的其实是「预判支持」。这是**误伤企业的错误信号**，性质比纯视觉问题严重。

**白话 + 算例**：甲公司是制造业专用设备企业。G-D 说「主板定位这一项对应 21 套官方套，逐套归属还没做」。原型把这句话渲染成一枚黄章「板块定位 · 待核查」，挂在企业信息卡上。用户的直觉解读是「这个企业定位不符合要求」；真实含义是「**这一项的结论目前只能预判支持，逐套明细我还没算**」。两句话在黄章里被压成了一句。

**建议**（已落地）：

1. **拆分语义**：值改为「**预判支持** · 待交易所实质判断」——业务侧结论与依据分离；judgment 项永不 `met` 的约束仍满足。
2. **新增非五态视觉 token** `.pill-e`（**虚线灰**，与五态均不同）：专表**工程状态**。灰色虚线 = 我方没做，不是企业不行。视觉上与 needs_review（琥珀实心）彻底分开，杜绝误读。
3. 三处同步：定位卡（新增 `#bp-eng` 行）、段② scope 行、指标列表末行。

**验收**：全页不再有以 needs_review 色呈现的「G-D 待接入」措辞；工程态徽章与五态徽章在视觉上可区分（虚线 vs 实心）。

## 2. P1：交互 / 专业性需修（6 项）

### U2 · 上市标准套卡默认全折叠，阈值要点不外露

新建页左栏列出官方套，用户必须逐个点开才能知道「这套要什么」。而阈值恰是决策第一信息。

**建议**：首套（前沿）默认展开，其余收起；折叠态在卡头下方给一行**阈值摘要**（去重后的 `req` 值串），要点一眼可见。**已落地**：卡高 134 / 86 / 86px，首套 `aria-expanded=true`。

### U3 · 指标列表筛选粒度不足（两档粗分 vs 契约五态）

原筛选只有「全部 / 未满足+不可判 / 仅待核查」三档，把 `not_applicable` 与 `indeterminate` 混在一起。契约层五态是硬的，视图层却看不出五态。

**建议**：细分五档 chip（与徽章同色），计数只数**当前可见列**。**已落地**：全部 9 / 满足 5 / 未满足 3 / 不可判 1 / 待核查 2 / 不适用 5。遗留：跨列口径（任一命中 vs 全部命中）尚无切换。

### U4 · 结果页无 result.json 导出，契约产物不可落地

引擎输出是单文件 `result.json`（设计 0004 §5），但原型只能看不能拿，评审者无法核对契约字段。

**建议**：结果页加「下载 result.json」按钮，按契约 v0.2 四段（`run` / `facts` / `layers` / `narrative_handoff`）由页面 mock 反推，并在按钮 tooltip **显式声明「由 mock 反推，非引擎产物」**。**已落地**：9 items / 19 checks / 3 sets / `recommendation=null` / 3 scenario（window_roll×2 + growth is_forecast）/ 5 disclaimers / 3 forbidden_claims / 8 citation。

> **P9 拍板 = A（2026-11-11），落地状态撤销**：用户质询「与需求无关」成立——需求文档的测评结果页无任何 JSON 导出；两按钮均为架构演示（服务契约参照实现角色），混入终端用户故事即成噪音。连同更早的「导出叙述 handoff」（导出内容为 result.json 四段之一的子集，页面已有静态预览区，纯冗余）一并移除（UI v0.5.1）；契约核对留给实现期引擎真实产物。

### U5 · 占位条文号看起来像正式引用

`3.1.2(一/二/三)` 是占位（规则库 `calibration_pending`，校准 #5 回填），但渲染上与真实条文号无区别 —— 读者会当作已核实引用转述。

**建议**：占位号统一加 `#5` 上标 + tooltip（指向 ADR-0005 校准管线），并保留 design 0006 §6 已知限制第 2 条。**已落地**：9 处。

### U6 · 口径 pill（归母 / 扣非孰低 / 自估）不可点，孰低取值过程无法核验

扣非孰低是审核实务最容易分歧的口径，原型只给一个标签，读者无从知道「逐年孰低还是先合计再孰低」「扣非缺失怎么办」。

**建议**：pill 点击弹窗，说明**口径规则**与已披露的孰低结果。**已落地**（弹窗说明逐年孰低顺序、扣非缺则整叶转 indeterminate、企业自估限定）。**归母/扣非分项数值不编造** —— 标注待设计 0006 字段全集落地后回填。

### U7 · 历史页结论列是自由文本，run_id 无法只读查看

历史表最后一列是一句话，人读得了、机器读不了，也无法点进去看某次测评长什么样。

**建议**：结论列结构化为「**套终态（五态逐套）+ 路径输出（前沿 / 排除）**」两列；「查看」带 run_id 进入**只读快照**（琥珀底横幅 + 锁定标识 + 退出按钮），快照态禁用下载。**已落地**：6 列结构化 + run 只读横幅。**诚实边界**：叶子明细尚未按 run 分档，横幅**显式声明**「下方仍为当前测评快照」，不伪装成历史数据。

## 3. P2：呈现层改进（7 项）

### U8 · 市值补录无单位切换，同一数字被误读

补录框只收「亿」，从别处抄来的「500000 万」需人工换算，且无从校验换算对不对。

**建议**：加「亿元 / 万元 / 元」下拉，实时折算并**对照两套门槛**（≥50 亿 / ≥100 亿）给 ✓/✗。**已落地**：输入 50 亿 → 第二套 ✓ 第三套 ✗；留空 → 「indeterminate（不按 0 处理，不计入 any 支路）」——直接复述缺数据三原则。

### U9 · 情景推演数值硬编码在 HTML 里

引擎接入后 `layers.gap.scenario` 由规则算出，页面硬编码必然对不上，且无法回归。

**建议**：抽 `SCEN` 常量 + `renderScen()` 渲染，HTML 只留容器。**已落地**：三张卡各 245px；growth 独立成卡并保留 `is_forecast` pill（window_roll 与 growth 语义不同，混在一张卡里会被读成同一类结论）。

### U10 · 键盘不可达：焦点不可见、弹窗不响应 Esc

焦点环是「能不能用键盘」的**唯一**信号。原实现依赖 `:focus-visible`，而渲染器实测不支持该伪类（`a.matches(':focus-visible')` → `false`），`html.kb :focus` 复合选择器同样不匹配 → 键盘用户**完全看不到焦点在哪**。

**建议**：焦点环由 JS 写 `.kb-ring` class（键盘模态显示、鼠标按下移除），配 `outline:2px solid #1d4ed8`（用字面 hex，`var(--brand)` 在该上下文不解析）；补 Esc 关闭 + 弹窗内 Tab 焦点收敛 + 折叠头 `aria-expanded` 同步 + 套卡头/历史卡改真 `<button>`。**已落地**。

### U11 · 缺口三分列在窄列下可读性不足

diff / required_delta / required_action 三列宽度按表头等分，实际数值长度差异大。

**建议**：结果页表格列宽按内容长度重新分配。**已落地**（v0.3 排版体检）。

### U12 · 计数守恒口径的呈现位置易误读

五态计数若与适用项数分列在不同区段，读者会把 `not_applicable` 计入分母。

**建议**：计数守恒归位段①，并在 §6 标注 `not_applicable` 单列不计入分母。**已落地**（v0.3）。

### U13 · 归因维度标注与设计 0005 §7.2 不一致

设计 0007 原写「2×2」，实为 5×3（评审 0004 V5 已判）。

**建议**：UI 同步 5×3 并落到有值的格。**已落地**（v0.3，评审 0004 处置同步）。

### U14 · 条文号占位未在已知限制中登记

§6 已知限制第 2 条原仅说「条文号为占位」，未与校准 #5 的关系联动。

**建议**：补「校准 #5 回填后替换」+ 与 U5 的 `#5` 上标互相指向。**已落地**。

## 6. 复核结论

**结论**：设计 0007 的**交互骨架与专业口径成立**，P0（U1）与 6 项 P1 已在 UI v0.4 全部修完，**可作为交互冻结基线**，并作为引擎出口（M6/M7 交互层）的参照实现。

**未覆盖**：规则阈值内容是否与现行法规一致（属校准 #5）；引擎产出的 `result.json` 字段形状与契约 v0.2 的一致性（实现期以 pydantic 模型为对拍基准；原型反推件已按 P9 = A 移除，不再作锚点）；移动端适配（§6 已知限制第 4 条，仍未做）。
